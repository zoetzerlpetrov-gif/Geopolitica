Fase 3 · Datos de archivo y SHA-256

Selecciona un archivo de hasta 100 MB. Se leen sus bytes en memoria, sin subirlo a un servidor ni ejecutar su contenido. La huella identifica esos bytes; no acredita veracidad, autoría ni ausencia de malware.

Esta edición no verifica firmas C2PA ni certificados TLS. Puedes registrar informes aportados en Fase 2, identificándolos como declaraciones de terceros. El análisis de fotos y documentos ya disponible permanece en la Caja del analista y las herramientas del mapa.


Cifrar y abrir respaldos JSON
El cifrado se realiza aquí mediante Web Crypto (AES-GCM y PBKDF2). Protege el archivo descargado; no cifra automáticamente el almacenamiento de Fase 1/2/4. La contraseña no se guarda ni se envía. Custódiala por separado: no hay recuperación por cuenta.
Abrir una copia cifrada
Descifrar no reemplaza registros. Para restaurar, importa el JSON en su fase; Fase 4 también abre directamente sus respaldos cifrados. Las copias en claro deben custodiarse.

Tutorial · Uso completamente web
1. Elegir la fase y entender dónde se guardan los datos
Abre esta dirección desde tu navegador. Fase 1 organiza preguntas; Fase 2 analiza registros; Fase 3 procesa archivos y respaldos; Fase 4 reúne información en expedientes. Los registros se conservan en el perfil y origen web usados. Otro navegador, otro dispositivo, una ventana privada o una dirección distinta pueden no tener los mismos datos.
2. Trabajar con Fase 1 y Fase 2
  1. Abre una fase desde el menú.
  2. Elige una sección, completa los campos y guarda.
  3. Para editar un registro, selecciona Editar y documenta el motivo solicitado.
  4. Exporta su respaldo JSON antes de cambiar de equipo o borrar datos del sitio.
Fase 2 permite calcular hashes, importar informes aportados y analizar texto de cabeceras. No ejecuta aplicaciones de escritorio ni inspecciona conexiones TLS.
3. Crear un expediente y relacionar información
  1. Abre Fase 4A y crea «Suministro QA».
  2. Usa Incorporar Fase 1/2 para copiar registros de este navegador, o importa sus respaldos.
  3. En Activos crea «Terminal QA», responsable Operaciones, identificador TERM-QA-01.
  4. En Entidades y eventos crea una interrupción de prueba.
  5. En Relaciones conecta evento → afecta → terminal y escribe el fundamento.
  6. Consulta Vista unificada para encontrar títulos y sus relaciones.
Las copias entre fases son explícitas, no sincronización automática. Al guardar se crea una versión documental; una edición simultánea desde otra pestaña produce conflicto en lugar de sobrescribir.
4. Incorporar y descargar un original
  1. En el expediente abre Originales y custodia.
  2. Selecciona un archivo de prueba no vacío de hasta 512 KiB.
  3. Indica origen, fecha con zona horaria, custodio declarado y motivo.
  4. Confirma la incorporación; se calcula SHA-256 en el navegador.
  5. Para una entrega posterior registra otra declaración de custodia.
  6. Al descargar se comprueba que la huella siga coincidiendo.
Máximo 4 MB por expediente, incluidos originales codificados. No hay antivirus ni certificación probatoria. El nombre del declarante no autentica su identidad.
5. Crear un respaldo cifrado
  1. Desde Fase 4 abre Respaldos y versiones, o exporta un JSON de Fase 1/2 y selecciónalo en Fase 3.
  2. Elige una contraseña de al menos 12 caracteres.
  3. Descarga el respaldo cifrado.
  4. Custodia contraseña y archivo por separado.
  5. Prueba abrir una copia antes de depender del respaldo.
La exportación de un expediente contiene su versión actual, originales y declaraciones de custodia; no todo el historial de versiones del navegador. La clave no puede recuperarse si se pierde.
6. Recuperar una copia o cambiar de dispositivo
Abre el sitio en el otro navegador. En Fase 4 selecciona el respaldo, introduce la contraseña y confirma abrir una copia nueva. Se validan estructura y hashes. Para Fase 1/2, descifra el respaldo en Fase 3 y restaura el JSON desde la fase correspondiente. El archivo importado no prueba identidad, custodia autenticada ni aprobación institucional.
7. Límites de esta edición web
Las cámaras, mapas, consultas y procesos públicos existentes siguen funcionando por web. No se ofrecen cuentas, colaboración privada, vigilancia individual con la página cerrada ni ejecución de herramientas de escritorio. GitHub Pages no tiene una base privada de usuarios. Esas capacidades requieren un servicio alojado y autenticado que no está configurado; no hay botones que pidan preparar tu equipo para activarlas.
En modo privado/incógnito o con restricciones de almacenamiento puedes perder los registros al cerrar. Si el navegador avisa de falta de espacio, no borres datos sin un respaldo comprobado.
